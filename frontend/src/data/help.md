# SecondLook 使用帮助

SecondLook 是一个**双智能体协作系统**:用户描述任务后,两个智能体分工协作完成。

## 核心概念

### 检查助手(评估智能体)

**后台质检者**:AI助手 负责执行并直接回答你的问题,检查助手 在幕后核查它的产出(核查优先、追问兜底):

- AI助手 每完成一轮执行,它会核查结果的完整性与可靠性:读真实源码核对发现、剔除误报、补漏
- 配置了测试环境时,对"疑似但不确定"的安全发现发送 PoC 动态验证;无测试环境则标注"仅静态、待动态确认"
- 会抽查复核 AI助手 引用的外部依据链接(CVE / 安全公告 / 官方文档)是否真实存在、来源是否可靠
- 任务收尾时提炼**重点与知识点**(3-8 条精选学习点),任务完成后可自动生成练习题(可在练习设置中关闭)
- 仅当它无法自己核查、且发现 AI助手 结果确有错误或缺失时,才会发出**修正指令**(主界面显示为醒目的"修正指令"卡片)
- 它的核查过程(思考/读码/验证/评估)展示在**任务详情侧栏**,不占用主对话流

### AI助手

负责**调用工具执行任务**:

- 内置 AI助手:直接使用你选定的 LLM 模型(评估模型可在「高级设置」指定)
- 外部 CLI agent:已配置且启用的外部 CLI(Qoder / DeepSeek / Codex),在提交任务页可切换

两者按**轮次协作**衔接:AI助手 直接按你的任务描述开始执行并回答你,每完成一轮,检查助手 在后台核查一次,发现问题才要求修正。默认最多 2 轮(检查助手能自己核查,很少需要修正)。**主对话流就是你和 AI助手 的对话**;检查助手 的过程在右侧"任务详情"侧栏。

### 引用复核

开启「复核 AI助手引用的网址」(智能体策略,默认开)后,检查助手 会抽查 AI助手 结论中引用的外部依据链接:

- 核对链接是否存在(404 → 已失效)、来源是否权威(官方公告/文档为权威,域名分级仅供参考)
- 部分安全站点(如 NVD)是脚本渲染页面,抓不到正文时只核对可达性,不臆断内容真伪
- 无法访问(超时/网络限制)只代表"复核无法完成",不会因此否定 AI助手 的结论
- 抓取在后端进行并有 SSRF 防护,单轮最多复核 3 个链接

### 验证动作(实验性)

开启「自行验证」后,检查助手 会在沙箱内调用 `http_request` / `run_python_code` 动态验证 AI助手 的发现(如确认 SQL 注入是否真实可利用)。验证动作有两种授权模式:

- `per_action`:每个动作执行前弹窗让你确认(显示完整 URL / 头 / 请求体或代码)
- `direct`:不弹窗,直接执行

可在「智能体策略」页设默认模式,任务创建时可覆盖。

## 页面导览

### 首页 `/`

欢迎落地页。点"提交新任务"进入任务提交页。左上角按钮可展开历史任务侧栏。

### 提交任务 `/tasks/new`

1. **选择场景**:场景提供预设 prompt 模板,选择后自动填入输入框;也可自由输入覆盖
2. **选择 AI助手 执行器与模型**:内置 AI助手 在此选择使用的模型(留空则用「高级设置」里的评估模型);若已配置外部 CLI(Qoder / DeepSeek / Codex)可在此切换
3. **高级设置(可选)**:点顶部「高级设置」入口配置 检查助手(启停 / 评估模型 / 允许自行验证)与执行命令确认模式;关闭 检查助手 即进入单 agent 模式
4. **填写任务描述**:尽量具体——目标、范围、约束、期望产物格式
5. **选择交付物来源**:Git 仓库 Tab 填写仓库地址与分支(AI助手 会克隆到沙箱中执行);或切到「上传 ZIP / 上传文件」Tab 上传压缩包/单文件作为交付物(仍需填写任务说明,上传为可选)
6. **点发送按钮**:后端立即返回 task_id 并跳转到任务详情页观看实时进度

### 任务详情 `/tasks/:id`

实时观看任务执行:

- **主对话流**:你和 AI助手 的对话(思考、工具调用、计划清单、每轮回答);检查助手 发现问题时,以醒目的"修正指令"卡片出现
- **任务详情侧栏**(右侧):检查助手的核查过程(按轮折叠:思考/读码核对/动态验证/引用复核/评估)与**重点与知识点**(任务收尾时检查助手提炼的 3-8 条精选学习点,带"值得学"标记的还可生成练习题)
<!-- practice-section-start -->
- **生成练习题**(任务完成后):重点与知识点区旁点「生成练习题」,把学习点改编为练习题,预览确认后入库(有候选题待确认时按钮显示「确认练习题(N)」)
<!-- practice-section-end -->
- **暂停 / 恢复**:运行中可随时暂停,补充信息后恢复执行;暂停期间可向智能体追加指令
- **历史任务切换**:左上角按钮展开侧栏,在多个任务之间快速切换

### 模型设置 `/models`

配置 LLM 凭据(API Key、Base URL、模型名)。支持多个凭据,提交任务时选用。

### CLI 设置 `/cli`

配置外部 CLI 凭据(如 Qoder 的 PAT、DeepSeek / Codex 的 API Key)。配置并启用后,在提交任务页可切换执行器。

### 智能体策略 `/agent-policy`

调整 检查助手 行为与执行命令策略(用户级默认,任务级可覆盖):

- **启用 检查助手**:开启后 AI助手 执行完即标记任务完成,检查助手在后台审查并产出「重点与知识点」与「建议深挖方向」;关闭后退化为单 agent 模式(AI助手 跑 1 轮即输出,不做后台审查)
- **自行验证(实验性)**:允许 检查助手 跑 PoC / HTTP 请求动态验证发现;安全审计类任务未显式设置时自动开启(实际验证仍需任务配置测试环境)
- **复核 AI助手引用的网址**:抽查复核 AI助手 引用的外部依据链接是否存在、来源是否可靠(默认开,结果仅供参考)
- **验证授权模式**:`per_action`(每动作弹窗确认)/ `direct`(直接执行)

### 技能管理 `/skills`

上传并管理自定义技能(AI助手 可调用的多步操作模板):

- 上传 zip 格式的 skill(内含 `SKILL.md`,支持 `<skill_name>/SKILL.md` 或根目录直接放)
- 上传后 AI助手 的 `list_skills` / `skill` 工具立即可用
- 技能仅自己可见,他人无法查看或使用
- 系统内置 skill(如 `check_sql_injection`、`check_hardcoded_secrets`、`check_ssrf`)只读,不能删除
- 自己上传的 skill 可在线编辑 `SKILL.md` 并热保存

### 自适应练习 `/practice`

根据你的掌握度自动出题复习,巩固审计 / 代码审查等场景的知识:

- **练习首页**:顶部一行操作头常驻——左侧动作(开始练习 / 出题进度 / 练习设置),右侧四项统计(能力估计 / 到期待复习 / 累计正确率 / 题库题数);每项统计的详细说明鼠标悬停即可看到(如发现 N 个知识点到期时会在悬浮里说明本次组卷优先安排复习题)。左侧目录跳转「错题回顾 / 题库管理 / 历史记录」三段,当前段随滚动高亮。点「开始练习」先选题数(4 / 8 / 12 / 16)再组卷;薄弱知识点全景不在本页,在知识点看板页
- **知识点看板 `/knowledge-board`**:顶栏一级导航「知识点看板」进入(与「自适应练习」并列),知识点按**学习主题**(安全 / 架构 / 编码 / 合同 + 自定义)分组为折叠区;含薄弱或待复习卡片的分区自动展开,区头点「练这个主题」可整主题开练,点卡片上的「专项练习」只练该知识点;每张卡片右上角有掌握状态徽章(薄弱 / 待复习 / 已巩固 / 学习中 / 未开始);旧路径 `/practice/board` 自动跳转过来
- **组卷规则**:后端按「到期复习 > 薄弱点 > 难度匹配 > 新题」的顺序选题,答案不下发
- **答题会话**:逐题作答(单选 / 判断),提交后即时判分并展示解析与知识点掌握度反馈;答题时可展开右侧源码栏对照来源代码。进入答题与本局统计后,操作头与左侧目录会隐去
- **生成练习题**:任务完成后,在任务详情页结果清单旁点「生成练习题」把审计发现改编为题目;也可在练习设置中开启自动出题,任务完成时自动生成(产出的候选题仍需预览确认才入库);两级质量关卡会自动拦截「叙述式送分题」与不看材料也能答对的常识题
- **练习记录**:练习首页目录的「历史记录」段(最近 8 周正确率折线 + 历史会话列表,展开会话看逐题作答明细);旧路径 `/practice/history` 自动跳转到该段
- **练习设置**(操作头上的「练习设置」,与设置页「练习设置」项同一入口):自动生成开关 / 出题前恢复工作区 / 出题思考模式 / 默认出题模型 / **学习主题管理**(内置主题可启用停用,可添加自定义主题——新任务的发现会自动分类到启用的主题并按其视角出题;停用的主题不再出新题,已有题目不受影响)
- 顶栏导航项右上角的红色数字表示到期待复习的题目数;出题进行中可点操作头上的「出题进度」展开右侧抽屉查看实时进度

### 记忆管理 `/memory`

以「文件」隐喻管理三类长期记忆,均为 Markdown 自由文本,注入到对应智能体的系统提示词:

- **用户偏好**(1 份,上限 2000 字符):注入 检查助手,影响评估倾向与判据
- **全局记忆**(1 份,上限 20000 字符):跨项目通用经验,同时注入 检查助手 与 AI助手
- **项目记忆**(N 份,按 `repo_url` 聚合,上限 20000 字符):任务完成后由 LLM 自动归纳生成,注入 AI助手;可编辑项目别名便于识别

预览用 `marked` 渲染 + `DOMPurify` 净化(防存储型 XSS)。Agent 策略已迁至 `/agent-policy`,本页只管记忆文本。

### 账号设置 `/settings`

(由顶栏齿轮按钮进入,不在主导航)

- GitHub / Gitee 账号绑定(用于私有仓库 clone)
- 登出设备管理
- 删除账号(需输入完整邮箱二次确认,硬删除级联清理所有数据)

## 任务运行中的弹窗

任务运行过程中可能弹出以下对话框:

### 验证动作授权(VerifyActionDialog)

开启「自行验证」且授权模式为 `per_action` 时,检查助手 每次执行 `http_request` 或 `run_python_code` 前会弹窗让你确认。弹窗显示完整请求(URL / 方法 / 头 / 体)或代码内容,你可选「拒绝」或「同意执行」。

### 危险命令确认(CommandConfirmDialog)

危险命令确认有两种场景,共用同一个弹窗组件:

**1. local 模式(无沙箱,`SANDBOX_MODE=local`)**

智能体调用 `run_command` 执行的危险命令(如 `rm -rf`、`curl | sh`、`sudo`、`mkfs` 等)会弹窗让你确认。命令在宿主机上直接执行,请确认内容无害后再同意。安全命令(`git status` / `ls` / `cat` 等)直接执行不拦截。

**2. CLI AI助手(`per_command` 模式)**

选择 qoder / deepseek / codex 作为执行器且命令确认模式设为「逐命令确认」时,CLI 执行危险命令前会通过 ACP 协议发送 `request_permission` 请求,前端弹窗显示命令内容让你确认。可在「智能体策略」页设默认模式,新建任务时也可单独覆盖。

- **自动批准**(默认):注入 YOLO 模式,所有命令直接执行不弹窗(速度快,适合可信任务)
- **逐命令确认**:每个危险命令弹窗确认(更安全,防容器破坏 / 资源耗尽)
- **Codex 限制**:`codex exec --json` 是非交互模式,不支持逐命令确认,选 `per_command` 时会自动降级为自动批准并警告。如需命令确认,请改用 qoder / deepseek。

**3. 内置 AI助手(`per_command` 模式,sandbox 模式下)**

选择「内置」执行器且命令确认模式设为「逐命令确认」时,内置 AI助手 执行危险命令前会推 `command_confirm` SSE 事件,前端弹窗显示命令内容让你确认。与 local 模式复用同一套机制(`_PendingCommandConfirm`)。

- **自动批准**(默认):sandbox 模式下危险命令直接执行(沙箱已隔离,破坏范围限于容器内)
- **逐命令确认**:sandbox 模式下危险命令弹窗确认(更安全,防容器破坏 / 资源耗尽)
- **local 模式特例**:无论选哪个模式,local 模式下 dangerous 命令始终推确认(宿主机直接执行,无法绕过)

## 快捷操作

### 任务详情页键盘快捷键

- `Enter` 在输入框中发送补充指令
- `Shift + Enter` 换行

### 新手引导

首次进入首页 / 提交任务页 / 任务详情页时会自动弹出新手指引气泡。可点击"跳过引导"关闭,完成后不再自动弹出。引导文案有大改时会递增版本号,老用户会重新看到引导。

> 若想重新查看新手引导:目前未提供入口。如需重看,清浏览器 localStorage 中 `secondlook:onboarding:completed:*` 相关 key 即可。

## 常见问题

### 提交任务后没反应?

- 检查浏览器控制台是否有 SSE 连接错误
- 确认模型凭据有效(API Key 未过期)
- 仓库地址是否可访问(私有仓库需先绑定 GitHub / Gitee)

### AI助手 报错"模型未配置"?

到「模型设置」配置至少一个 LLM 凭据,提交任务时选择该模型。

### 检查助手 一直追问?

它的追问是为了澄清意图,确保任务完整。如实回答即可。若问题与任务无关,可在回答中说明。

### 任务被暂停了?

- 可能是 检查助手 主动打断(发现需要用户澄清)
- 也可能是手动点了暂停按钮
- 在暂停状态下输入补充信息后点"恢复"即可继续

### 想更换执行器但下拉框没有选项?

到「CLI 设置」配置外部 CLI 凭据并启用,回到提交任务页即可看到新选项。

### 想让 AI助手 自动按固定步骤执行?

到「技能管理」上传或使用内置技能(如 `check_sql_injection`),AI助手 会在合适时机主动调用。

### 验证动作弹窗太频繁?

到「智能体策略」把「验证授权模式」改为 `direct`,验证动作将不再弹窗直接执行(注意:这会放行所有 PoC / HTTP 请求,请确认测试环境隔离)。

### local 模式下危险命令弹窗太多?

local 模式下,智能体的命令在宿主机直接执行,危险命令会弹窗确认。建议切到 `SANDBOX_MODE=sandbox` 用沙箱隔离,就不会有这些弹窗。生产环境务必用 sandbox 模式。

### local 模式能用 CLI AI助手吗?

可以(默认开启,`SANDBOX_LOCAL_ALLOW_CLI=false` 可关闭)。bridge 与 CLI 会直接运行在宿主机真实环境中,注意以下限制:

- **需预装 CLI**:local 模式不会自动安装,报"宿主机未找到 xxx"时请先手动安装(如 `npm install -g`),或在配置中把对应 `*_CLI_BIN` 指向绝对路径
- **无隔离**:CLI 自带的 shell/工具在宿主机真实执行,不受危险命令弹窗和原生隔离保护(那些只覆盖内置执行器的 `run_command`),仅建议开发/调试使用
- **凭证经环境变量注入** CLI 进程,CLI 内的工具可读到(如 `printenv`)
- **私有仓库**:local 模式跳过 git 凭证注入(避免污染宿主机 `~/.gitconfig`),CLI 会话内克隆/拉取私有仓库不可用(任务预克隆不受影响)
- **进程残留**:后端异常退出可能残留 bridge/CLI 进程与 `sandbox_local_*` 临时目录,需手动清理
- Codex 的配置写在任务临时目录(经 `CODEX_HOME` 重定向),不会读写你宿主机的 `~/.codex`

### CLI AI助手命令弹窗太多?

到「智能体策略」把「CLI 命令确认模式」改为「自动批准」,CLI 执行危险命令时将不再弹窗直接执行(注入 YOLO 模式)。注意:这会放行所有危险命令,请确认任务可信且沙箱隔离到位。新建任务时也可在「高级设置」单独设置覆盖智能体策略页的默认值。
