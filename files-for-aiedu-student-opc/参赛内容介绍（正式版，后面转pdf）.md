## 一、作品背景与概要

AI 能替你生成很多东西，但它们出了问题，责任仍然是你的。这是今天大学生创业者普遍面对的处境：用 AI 写出小程序、生成合作协议、做出路演材料，却看不懂、不敢改、不敢用。

AI 技术合伙人・SecondLook 是一个面向大学生个人创业（OPC）场景的智能体平台。用户把自己的项目或 AI 生成的结果（代码仓库 / 压缩包 / 计划书文本）交给它，AI助手根据用户的提问和任务要求进行分析审查，按需读取代码、调用工具核验；检查助手随后在后台逐条核对结论——回到真实源码取证、核查引用的外部资料是否可靠，再把无法自行确认的缺口整理成「建议追问方向」交由用户一键触发。

在此之上，产品把审查中真实发现的问题自动改编成最小化练习，按 SM-2 遗忘曲线推送，让用户在下一次踩坑之前补上短板。练习素材来自用户自己的项目。

教学产品有题库但没有你的上下文，审查工具有上下文却教不会人。AI 技术合伙人・SecondLook 两者兼得，让一个大学生的个人团队以低成本获得原本需要雇一名技术合伙人才有的判断力。

## 二、目标用户

一人公司（OPC） / 创业者大学生独立开发者

## 三、应用场景

聚焦「AI Agent 支撑个人或小团队完成从创意到落地的创业实践」，当前落地三个场景：

1. **代码审查**
   提交 GitHub / Gitee 仓库地址、ZIP 压缩包或单文件，输入需要审查的维度或模块即可发起任务。
2. **合同 / 文书审查**
   面向学生创业常见合同、商业计划书等，智能体分析并给出修改建议。
3. **按需能力提升（贯穿前两个场景）**
   审查报告中的真实问题 → 知识点看板 → 组卷练习 → 作答判分与解析。

## 四、解决的教育痛点

**痛点一：双创教育里，「会用 AI 干活」被默认等于「会判断干得对不对」。**
课程鼓励学生用 AI 快速做出 MVP，但学生交上来的项目，师生其实都看不懂 AI 生成的那部分。结果是双创实践产出越来越多，验收环节却仍然靠「能跑就行」。**没有人在教学生「审」。**
→ 解法：把「审查 AI 生成物」做成产品的主功能，让每一次交付先过一道机器质检＋人话解释；再用「审查维度展示」把审查过程本身变成教学内容。

**痛点二：安全教育、合同教育、编程教育都在教，但用的都是别人的案例。**
学生做错的题、踩过的坑不在课程材料里；课程题库与学生的真实项目完全脱节，学的时候觉得懂了，下次照样踩。
→ 解法：练习题素材 100% 来自用户自己刚提交的项目，学习动机与真实风险直接挂钩；每个风险点用大白话讲清「为什么是坑、有什么后果」，支撑当下决策，而不是等学完再做决策。

**痛点四：AI 生成内容进入教学与创业场景，缺少人工复核与留痕机制。**
指南「合规与安全总则」要求 AI 生成内容必须人工审核。多数 AI 工具直接把结论给用户，无法追溯结论从哪来。
→ 解法：双智能体质检本身就是内建的人工复核前置环节——检查助手不重复 AI助手的说法，而是回到真实源码逐条核对、核查引用的外部资料是否真的存在；核实不了的不硬下结论，而是在该条发现上显式标注「仅静态分析，待动态确认」。把「未取证的判断」和「已核实的事实」分开呈现，全过程流式留痕可回放。

## 五、AI Agent 设计思路

### 5.1 两个智能体职责分离

单个 AI 审查代码的典型失效模式是**说得像真的**：报告写得漂亮，结论却没取过证，用户无法分辨，于是「审查」退化成了另一份需要被审查的 AI 生成物。

本作品的核心设计判断：**把生成与验证拆成两个职责严格分离的智能体。**

- **AI助手（执行）**：按任务描述规划并完成分析，工具调用包括克隆仓库、检索代码、运行静态代码检查、执行脚本等。任务在 AI助手 完成时即标记完成，保证用户拿到结果的时间可预期。
- **检查助手（质检）**：从任务描述中定义审查维度，在后台完成一轮完整审查，输出两样东西——「关键要点／知识点」与「建议追问方向」。

### 5.2 从审查到学习的数据链路

`真实发现 → 打 practice_worthy 标签 → 归入知识点看板主题 → 出题（LLM 生成，draft 预览确认后才入库）→ SM-2 排期 → 作答判分与解析 → 掌握度回流成长数据`

出题不是独立功能，而是审查结果的下游投影。因此题库不可能与学生项目无关——这是本产品与一切通用刷题工具最根本的结构差异。

## 六、技术创新点

1. **验证者优先的双智能体质检机制**（不是两个 AI 闲聊）
   检查助手被剥夺改代码的权限，只有取证职责：回源码（或文书原文）逐条比对、抽查外部引用的真实性与权威性、核实不了时不硬判。「AI 说的」和「验过的」在报告里是两类东西。
2. **审查结论直接生成教学内容——素材同源，不需要题库**
   练习题由用户自己项目里的真实发现改编而来，`practice_worthy` 标签决定出题优先级。同一份审查上下文既产出风险报告又产出练习，这是「审查 ＋ 出题」共用一套上下文的架构结果，而非在审查工具上加了个刷题页。
3. **「敢不敢上线」的决策式输出，而非技术分数**
   报告终点是一个非技术创始人能做决定的结论＋大白话后果解释，把结构化风险翻译成创业决策。
4. **可插拔执行器抽象层（ACP 协议）**
   内置 ReAct 智能体与外部 CLI（Qoder / DeepSeek Harness / Codex）在同一任务模型下可切换；更换执行层不改业务主干，使产品能持续吃到最新智能体能力红利。
5. **结论自带「取证状态」，把不确定性显式交给用户**
   每条发现的元数据带 `verified` / `verify_method` / `ref_status` 等状态位：是经源码核实、经引用核查，还是「仅静态分析，待动态确认」。用户一眼能分清哪些结论可以直接拿去拍板、哪些还需要自己再看一眼。多数审查工具把所有结论以同等确定性呈现给用户，而这恰恰是 AI 生成物最危险的地方。
   支撑这一点的验证工具链已实现并带安全边界：PoC 请求的 base 地址锁定为任务配置的测试环境、不可由模型篡改（防 SSRF），逐条人工授权可选，执行落在隔离容器内。因需要被测项目提供可访问的测试地址，本作品**尚未完成该链路的端到端实测**，故不纳入演示与成效数据。
6. **场景矩阵的可复制架构**
   审查＋出题的组合不绑定代码：文书审核场景以极小成本接入，证明同一架构可迁移到合同、路演、财税等创业任务，支撑「AI Agent 支撑个人或小团队完成创业任务」这一赛道主线，而不是做一个单点功能页面。

## 七、应用价值

- **对学生创业者**：以接近零边际成本获得原本只有雇一名技术合伙人才有的验收能力，把「不敢上线」变成「知道该改哪三行」
- **对双创教育**：提供一套过程性、可核查的实践评价抓手——学生的交付物、系统发现的问题、学生的修复与练习表现构成完整链条，教师讲评有素材
- **对教育导向**：把 AI 时代最稀缺的能力从「会写」重新定位为「会审」，直接回应「培育适应未来社会的复合型人才」「构建人机协同的教育新生态」的大赛主题
- **对 OPC 生态**：验证了「一个人 ＋ 一队智能体」可以承担过去需要分工协作的创业任务，且验证结论可复现

## 八、后续优化方向

| 优先级 | 方向 | 说明 |
|---|---|---|
| **最高** | 沙箱内 PoC 动态验证的端到端实测 | 工具链与安全边界已实现，缺的是**可访问的待测靶场**：下一步准备一个自带注入点的样例服务，配置 `test_env_url` 后跑通「发现 → 生成 PoC → 容器内实际触发 → 结论标为已验证」全链路，并把验证条数纳入成效数据与演示视频 |
| 高 | 审查场景矩阵扩展 | 路演材料 / BP 审查（检查助手化身评委逐条追问，演示效果最佳）、财税报价、营销合规文案、市场调研 |
| 高 | 出题形态升级 | 从选择题扩展到真实场景实验（类 PortSwigger Lab 的网络安全实操），以及条款改写类主观题的自动评分 |
| 中 | 教师 / 教练端 | 班级管理、学习进度与共性薄弱点聚合，使一套系统同时服务个人创业实践与课堂集体实训 |
| 中 | 规模化成效验证 | 在课程与双创基地做对照式试点，补齐「实施显著性」所需的教学效率与学习收益量化数据 |
| 中 | 移动端 / 小程序 | 降低学生随身使用的门槛 |
| 低 | 能力地图与学习路径 | 在试点数据积累后再做，避免过早把产品拉回系统化教学 |

## 十六、安全与合规机制

对应指南「十一、合规与安全总则」及评分项「技术规范性（25 分）」：

- **AI 内容人工复核**：检查助手作为强制的第二道验证，把未取证判断降级为需用户主动触发的建议；报告支持用户反馈修正，题库条目须经 draft 预览确认才入库
- **凭证与隐私保护**：Git 访问令牌以 Fernet 对称加密存储；日志在处理器层统一脱敏（令牌值过滤为 `***`），Gitee 将 access_token 置于 URL 查询串并被 httpx 以 INFO 记录的情况已专门覆盖；克隆完成后从工作区抹除带令牌的 URL，防止泄露随下载扩散
- **数据最小化与授权范围**：Gitee 仅申请 `user_info`（登录）与 `projects`（仓库绑定）两项必要 scope，不过度索取权限
- **执行环境隔离**：智能体的所有工具调用运行在容器化沙箱内，受 CPU／内存限额与会话超时回收约束；动态验证权限支持逐条人工确认（`per_action`）与直连（`direct`）两种模式，由用户选择；PoC 请求的 base 地址锁定为任务配置的测试环境、不可由模型篡改，后端服务器地址不暴露给测试环境（防反向探测与 SSRF）
- **危险操作确认**：「AI助手确认策略」可要求命令级人工确认
- **上传安全**：ZIP 做 zip-slip 路径穿越防护及大小／数量上限校验；二进制文件不做在线预览，仅提供下载
- **接口与故障安全**：对外部平台调用按错误语义分类（平台明确拒绝 / 令牌失效 / 幂等可重试的网络与 5xx），单一用途的授权码绝不重放
- **SSRF 加固**：智能体核查外部引用（CVE / 公告 / 官方文档）时对内网地址与内网解析做防护
- **合规取向**：优先选用符合国内数据安全与网络监管要求的模型与平台；作品面向高等教育与创业实践场景，不涉及未成年人数据采集
