## 一、作品背景与概要

AI 能替你生成很多东西，但它们出了问题，责任仍然是你的。这是今天大学生创业者普遍面对的处境：用 AI 写出小程序、生成合作协议、做出路演材料，却看不懂、不敢改、不敢用。

AI 技术合伙人・SecondLook 是一个面向大学生个人创业（OPC）场景的智能体平台。用户把项目或 AI 生成的结果（代码仓库 / 压缩包 / 文件）提交给它，AI助手按提问与任务要求完成分析（按需读取代码、执行静态检查与脚本）；检查助手随后在后台独立复核，只取证、不改代码——回到真实源码（或文书原文）逐条比对、核查引用的外部资料是否可信，核实不了的不硬判，再把 AI助手未覆盖、需补查才能闭环的方向整理为「建议追问方向」，由用户一键交回 AI助手继续。

在此之上，产品把审查中真实发现的问题改编成练习题：素材来自用户自己的项目，每道题可回指其来源审查项。题目按 SM-2 遗忘曲线排期，到期在看板标为「待复习」并优先进入组卷，让用户在下一次同类问题出现前补上短板。

教学产品有题库但没有你的上下文，审查工具有上下文却不负责教会你。AI 技术合伙人・SecondLook 两者兼得，让一个大学生的个人团队以低成本获得原本需要雇一名技术合伙人才有的判断力。

## 二、目标用户

一人公司（OPC） / 创业者大学生独立开发者

## 三、应用场景

聚焦「AI Agent 支撑个人或小团队完成从创意到落地的创业实践」，当前落地三个场景：

1. **代码审查**
   提交 GitHub / Gitee 仓库地址、ZIP 压缩包或单文件，输入需要审查的维度或模块即可发起任务。
2. **合同 / 文书审查**
   面向学生创业常见合同、商业计划书等，智能体分析并给出修改建议。
3. **按需能力提升（贯穿前两个场景）**
   审查报告中的真实问题 → 知识点看板 → 组卷练习。

## 四、解决的教育痛点

**痛点一：「会用 AI 干活」不等于「会判断干得对不对」。**
学生能用 AI 快速做出 MVP，可 AI 生成的那部分到底对不对，却没人教过怎么判断。于是项目越做越多，验收环节仍然靠「能跑就行」。没有人在教学生「审」。
→ 解法：把「审查 AI 生成物」设为产品核心功能，让每次交付都附带一次独立复核；再让复核结论与证据逐条可见，把核查过程变成可学的示范。

**痛点二：编程教育、双创教育都在教，但用的都是别人的案例。**
学生做错的题、踩过的坑不在课程材料里；课程题库与学生的真实项目脱节，学的时候觉得懂了，下次照样踩。
→ 解法：练习题素材 100% 来自用户自己刚提交的项目，学习动机与真实风险直接挂钩；每个风险点讲清「为什么是坑、有什么后果」，支撑当下决策，而不是等学完再做决策。

## 五、AI Agent 设计思路

### 5.1 证据驱动的可信审查

单个 AI 审查代码的典型失效模式是「说得像真的」——报告写得漂亮，结论却没取过证，用户无法分辨，于是「审查」退化成另一份同样需要被审查的 AI 生成物。本产品要回答的第一个问题就是：**谁来回审「审查者」？**

**做法**：把「产出」与「复核」拆成职责分离的两段：

- **AI助手（产出）**：面向用户，按任务要求规划并完成分析（克隆仓库、检索代码、跑静态检查、执行脚本等）。任务在 AI助手 结束时即标记完成，用户拿到结果的时间可预期。
- **检查助手（复核）**：在后台独立复核，**只取证、不改代码**。它按用户意图定出 3–5 条审查维度作为审查计划，逐项回到真实源码（或文书原文）比对，并以结构化「审查项」输出——每条按**「待核实对象 → 审查结论 → 原始证据 → 分析依据 → 验证测试 → 可追问内容」**组织，按核实结果归入三档：**已核实成立 / 已核实不成立 / 待核实**。最后另出两样产出：「关键要点·知识点」与「建议追问方向」。

### 5.2 从审查到学习的数据链路

真实发现 → 标记「有出题价值」→ 归入知识点看板的学习主题 → 出题（模型生成，草稿预览确认后才入库）→ 按间隔重复（SM-2）排期 → 作答判分与解析

出题不是独立功能，而是审查结果的下游投影；因此题库天然与学生自己的项目相关——这是本产品与通用刷题工具最根本的结构差异。

### 5.3 主动提示用户未考虑到的审查维度

审查只能覆盖用户问到的范围，用户没想到的维度仍是盲区。为此产品另设一路后台轻量推荐：仅基于用户提问与 AI助手的对话，给出 0–3 条「用户尚未问及、但该类交付物值得一看」的审查维度，用户一键即可交回 AI助手 继续审查。

### 5.4 子智能体按需并行

一次审查往往要同时覆盖多个维度，逐项串行核查会让用户等待成倍增长。本产品对两个内置智能体（AI助手、检查助手）采用同一做法：**把「把任务拆给子智能体并行处理」做成智能体自己掌握的工具，由模型在运行时按需调用**——需要时才拆开并行，不需要时仍单线处理。

**AI助手**可调用工具 `dispatch_review_subtasks`，把选定子任务拆给多个只读子流程并行核查：

- **只读**：子流程不得修改工作区，只能查证。
- **规模受限**：每条子流程有迭代次数与时间上限；超时则带已得结论收尾，不影响其他子流程。

**检查助手**可调用工具 `dispatch_review_subagents`，把审查计划中的条目拆给多个子流程并行核查：

- **核查并行、落笔串行**：并行只用于查证；知识点提炼与结论输出仍在汇总后统一完成。
- **规模受限**：每条子流程有迭代次数、时间与取证次数上限；超时则收尾。

## 六、技术创新点

1. **审查与教学同源**
   通用审查工具只出结论，通用刷题产品只有与用户项目无关的题库；本产品让结论与练习出自同一份审查证据链：题目可回指其来源审查项与源码证据，题库随项目增长自更新

2. **可插拔的执行层（统一接入协议）**
   内置智能体与外部命令行智能体（Qoder CLI / DeepSeek Harness / Codex）经 ACP 协议统一接入、可随时切换；更换执行层不改业务主干，使产品能持续将最新的智能体能力转化为业务价值。


## 七、应用价值

- **对学生创业者**：以接近零边际成本获得原本只有雇一名技术合伙人才有的验收能力，并通过持续使用与练习，逐步把验收能力真正掌握到自己手里
- **对双创教育**：提供一套过程性、可核查的实践评价抓手——学生的交付物、系统发现的问题、学生的修复与练习表现构成完整链条，教师讲评有素材
- **对教育导向**：把 AI 时代最稀缺的能力从「会写」重新定位为「会审」，直接回应「培育适应未来社会的复合型人才」「构建人机协同的教育新生态」

## 九、安全与合规机制

- **凭证与隐私保护**：Git 访问令牌以 Fernet 对称加密存储；日志在处理器层统一脱敏（令牌值过滤为 `***`）
- **数据最小化与授权范围**：Gitee 仅申请 `user_info`（登录）与 `projects`（仓库绑定）两项必要 scope，不过度索取权限
- **执行环境隔离**：沙箱模式部署下，智能体的所有工具调用运行在容器化沙箱内
- **上传安全**：ZIP 做 zip-slip 路径穿越防护及大小／数量上限校验；二进制文件不做在线预览，仅提供下载
