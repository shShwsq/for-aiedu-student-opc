## 三、录制前准备清单

### T−2 天（数据与素材）

- ☐ 准备**演示样例仓库**：一个典型的 vibe coding 翻车项目（含硬编码密钥／SQL 拼接／无限量调用大模型 API 的死循环其中 2–3 项），公开或可访问；仓库名建议 `demo-vibecoding-mvp`，一眼能看懂
- ☐ 准备**合同样例** txt/md 一份：自编的学生创业合作协议，埋入「知识产权全部归甲方」「违约金单向条款」「验收标准模糊」三处问题（指南说明文书场景需上传 txt/md 纯文本，docx/pdf 无法在线审阅）
- ☐ 创建**演示账号**：邮箱用 `secondlook.demo@…` 这类明显非个人邮箱；昵称「演示用户」；密码提前存好，避免录制时输错或露出密码管理器
- ☐ 跑通一次完整任务，记录真实耗时与发现条数 → 填进第五节数据表；**确认检查助手在该仓库上确实回源码逐条核对，并输出「检查完成」与取证状态标注**（本次演示不含 PoC，不需要配置测试环境地址）

### T−1 天（技术准备）

- ☐ 检查 `http://your-server-ip` 可用性、模型额度余量（**429 限流会直接毁掉一段实拍**，额度留足两次完整任务的量）
- ☐ 设置里确认：检查助手开关＝开。动态验证权限（`per_action` / `direct`）控的是 PoC 类动作，**本片不演示 PoC，保持默认即可**，录制时也不要去点这个开关
- ☐ 浏览器：1920×1080、缩放 110%–125%（字号在评审的小屏上才看得清）、隐藏书签栏、退出个人账号、关所有通知（微信／钉钉／系统弹窗全部静音）
- ☐ 录屏：OBS，1080p / 30fps / CRF 23；系统声音开、麦克风单独一路（便于替换口播）
- ☐ **脱敏检查**（最重要，指南淘汰项含数据造假与违规内容）：
  - ☐ API Key／密钥配置页（设置 → 模型、CLI 设置）绝不出镜
  - ☐ Git 令牌、URL 中的凭证不出镜（应用已做日志脱敏，但录屏要自己别点开）
  - ☐ 不展示他人邮箱、手机号、真实同学姓名
  - ☐ 桌面干净，浏览器标签页只留演示页

### 开录前 10 分钟

- ☐ 先录 5 秒黑场，防止剪辑时开头撕裂
- ☐ 深呼吸，口播分两段录（先录屏拿画面，再配解说）——比边操作边说更容易控制时长
- ☐ 手边放一张纸写上三个数字：任务耗时、发现条数、高危条数（段落三要念）

## 六、拍摄、剪辑与导出

- **推荐录制流程**：先纯录屏跑通完整一次任务（不要边说边录，容易卡壳），再按第四节的口播稿配音，最后按时间码对齐。**配音可以重录，实拍不能重来。**
- **加速规则**：2C、2F 可 2–4 倍速并在画面角标标出「×4 加速 · 原速 X 分 Y 秒」；**2D 至少保留一段 15 秒以上不加速的实拍**，这是真实性的锚点。所有加速都要标明原速，否则有摆拍嫌疑。
- **画面**：1920×1080；浏览器缩放 110%–125%；鼠标移动放慢、点击处开高亮；关键结论区用画面局部放大（剪映 / OBS 场景缩放），不要加过多花字。
- **字幕**：全程硬字幕（评审可能静音观看）；每段落开头挂章节条 `第一段/第二段/第三段 + 时长`；术语第一次出现时在字幕里给出人话解释。
- **导出**：MP4 / H.264 / 1080p / 帧率 30；CRF 23–26 之间试一版，8 分 30 秒通常落在 200–350MB。若仍超 500MB，降到 720p 或 CRF 26–28，**不要缩短内容来迁就体积**。
- **命名与留档**：`AI技术合伙人SecondLook-演示视频-8分30秒.mp4`；保留未压缩原始录屏与工程文件，作为「真实使用过程」的佐证，可一并放进支撑材料。
- **交付前双重自检**：① 时长与分段（在剪辑软件里核对三个边界点是否落在 02:00 / 07:30）② 体积 ≤500MB ③ 全片无密钥、无真实个人信息、无第三方未授权素材。

## 七、风险与兜底预案

| 风险 | 征兆 | 处置 |
|---|---|---|
| 模型限流（429） | 输出中断、重试日志 | 应用侧已有指数退避重试；录制前预留两倍额度。**当天额度不足时，改用前一晚那次真实运行的历史回放录制**（系统保留完整留痕），并在口播里如实说明「这是同一次真实运行的完整留痕回放」——绝不拼接成一次不存在的运行 |
| 任务耗时远超预期 | 段落二超时 | 2C／2F 提高加速倍数并标注原速；缩短 2H 文书彩蛋到 15 秒；**不许砍 2D** |
| 沙箱服务不可用 | 工具调用报错、克隆或执行失败 | 段落二全程依赖沙箱（AI助手 在容器内跑工具），必须用沙箱模式重录；切勿用本地模式冒充沙箱模式 |
| 公网地址录制时打不开 | 网络／服务挂了 | 提前录一份段落一＋二的备份；准备 `SANDBOX_MODE=local` 的本地实例仅作界面应急，同时口播中不得声称是公网环境 |
| 检查助手给出的结论与 AI助手 高度一致、无戏剧性 | 画面平淡，2D 撑不起来 | 换一个漏洞更明显的样例仓库（硬编码密钥＋SQL 字符串拼接最直观）；2D 的台词重点放在「未验证被显式标注」这一条上，而不是放在「抓到多少个漏洞」上 |
| 报告出现中英混杂或过长 | 字幕读不顺 | 录制前用同一仓库预跑，把过长发现的展示方式在剪辑时用局部放大＋字幕改写处理；不改数据本身 |
