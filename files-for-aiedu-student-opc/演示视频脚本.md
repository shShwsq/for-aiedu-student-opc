# 演示视频脚本 · AI 技术合伙人・SecondLook

> 赛道：大学生 OPC 创新创业 AI Agent ｜ 录制环境：`http://your-server-ip`（公网部署，OpenSandbox 沙箱模式）
> **目标总时长 8 分 30 秒**（官方上限 10 分钟），文件 ≤500MB，MP4
> 分段严格按指南：概述 ≤2min ｜ 核心场景演示 ≤6min ｜ 效果总结 ≤2min

---

## 一、硬性约束

| 约束 | 指南出处 | 本脚本安排 |
|---|---|---|
| 总时长 ≤10 分钟 | 六(四)3 | 目标 8:30，留 90 秒缓冲 |
| 概述 ≤2min | 六(四)3 分段规范 | 段落一 `00:00–02:00`（正好 2:00，不得超） |
| 核心场景演示 ≤6min | 同上 | 段落二 `02:00–07:30`（5:30） |
| 效果总结 ≤2min | 同上 | 段落三 `07:30–08:30`（1:00） |
| 文件 ≤500MB | 同上 | 1080p H.264，见第六节压缩参数 |
| 必须展示真实使用过程 | 五(三) | **不摆拍、不伪造结果**；允许录制作业分段与加速，但一次任务的所有数字必须来自同一次真实运行 |
| 必须覆盖五个环节 | 五(三) | 用户提出任务 →（2B）／AI Agent 执行 →（2C＋2D）／生成结果 →（2E）／用户应用结果 →（2F＋2G）／支撑个人或小团队完成创业任务 →（段落三 OPC 回顾） |

**合规小技巧**：在视频里加三条章节字幕条——`第一段 · 作品概述`／`第二段 · 核心场景演示`／`第三段 · 效果总结`，并各自标注时间长度。评审按分段规范核查时，一眼就能看到合规，这是几乎白送的分。

|---|---|---|---|
| 04:30–04:50 | AI助手 总结落定、任务标记完成 → 右侧 **Agent2Panel** 头部出现「**检查中**」badge → 思考流开始逐段滚动（**不加速，实拍 15–20 秒**） | AI助手 一完成，任务就标记结束了，用户不用等第二个智能体。但如果我们继续看——检查助手此刻才在后台开始工作。它是**独立于 Qoder CLI 的第二个智能体**，被允许的权力只有取证，不能改材料。 | `AI助手 完成 = 任务完成`<br>`检查助手 只读 · 只验 · 不改` |
| 04:50–05:10 | 检查助手 tool_call 卡片出现：`[agent2 质检] read_file bp.md offset=… max_lines=…` → tool_result 带回**带行号的原文**；屏幕上一条 AI助手 结论与 BP 原文并列出现；重点拍**某一条被下调严重度、或结果 metadata 里 `verified=pending / verify_method=static` 被前端渲染为「仅静态分析，待动态确认」标签**的那一刻（不加速） | 比如这一条。它没有直接采信「这里数字自相矛盾」，而是把那段按行号读出来，一字一字对：这个数真的没算清吗？引用段落对不对得上？严重度有没有夸大？——**BP 不是代码，没有可运行的测试环境**，所以它不硬判“已确认”，而是就地打一个「仅静态分析，待动态确认」的标签。 | `只读工具回原文逐行核对`<br>`verified=pending · verify_method=static` |
| 05:10–05:25 | 画面切到 **引用核查** tool_call 卡片：`check_reference url=https://… claim=…` → tool_result 里返回 `ref_status / ref_authority / snippet`；某条被标为 `ref_status=unreachable` 或 `ref_authority=unknown` 的显示 1–2 秒 | 第二种取证更关键：AI助手 若引用了外部依据（行业报告、政策文号），检查助手会用 **`check_reference`** 在后端安全抓取，核对链接存不存在、来源权威不权威。抓取失败时它不会断言“引用造假”，而是老实标“复核无法完成”——这是防止把网络问题当结论。 | `引用真实性核查 · SSRF 加固`<br>`unreachable ≠ 造假` |
| 05:25–05:30 | Agent2Panel 头部 badge 切到「**检查完成**」→ 下方出现「建议追问方向」卡片（`suggestions` 0–3 条） | 检查完成。剩下的缺口它不自作主张，而是整理成 0–3 条「建议追问方向」，一键就能触发下一轮。 | `suggestions 0-3 条 · 一键追问` |

## 六、拍摄、剪辑与导出

- **推荐录制流程**：先纯录屏跑通完整一次任务（不要边说边录，容易卡壳），再按第四节的口播稿配音，最后按时间码对齐。**配音可以重录，实拍不能重来。**
- **加速规则**：2C、2F 可 2–4 倍速并在画面角标标出「×4 加速 · 原速 X 分 Y 秒」；**2D 至少保留一段 15 秒以上不加速的实拍**，这是真实性的锚点。所有加速都要标明原速，否则有摆拍嫌疑。
- **画面**：1920×1080；浏览器缩放 110%–125%；鼠标移动放慢、点击处开高亮；关键结论区用画面局部放大（剪映 / OBS 场景缩放），不要加过多花字。
- **字幕**：全程硬字幕（评审可能静音观看）；每段落开头挂章节条 `第一段/第二段/第三段 + 时长`；术语第一次出现时在字幕里给出人话解释。
- **导出**：MP4 / H.264 / 1080p / 帧率 30；CRF 23–26 之间试一版，8 分 30 秒通常落在 200–350MB。若仍超 500MB，降到 720p 或 CRF 26–28，**不要缩短内容来迁就体积**。
- **命名与留档**：`AI技术合伙人SecondLook-演示视频-8分30秒.mp4`；保留未压缩原始录屏与工程文件，作为「真实使用过程」的佐证，可一并放进支撑材料。
- **交付前双重自检**：① 时长与分段（在剪辑软件里核对三个边界点是否落在 02:00 / 07:30）② 体积 ≤500MB ③ 全片无密钥、无真实个人信息、无第三方未授权素材。

## 七、风险与兜底预案

| 风险 | 征兆 | 处置 |
|---|---|---|
| **BP 上传了 docx/pdf** | 任务报告里发现智能体“没看内容”直接总结，或 results 为空、不生成题 | ⚠️ **重录**，将 BP 先导成 txt/md（`pandoc bp.docx -t plain -o bp.txt` 或直接交一份手改纯文本）；绝不拼接成一次不存在的运行 |
| 模型限流（429） | 输出中断、重试日志 | 应用侧已有指数退避重试；录制前预留两倍额度。**当天额度不足时，改用前一晚那次真实运行的历史回放录制**（系统保留完整留痕），并在口播里如实说明「这是同一次真实运行的完整留痕回放」——绝不拼接成一次不存在的运行 |
| 任务耗时远超预期 | 段落二超时 | 2C、2G 提高加速倍数并标注原速；副场景 2G 从 0:40 压到 0:25；**不许砍 2D** |
| 沙箱服务不可用 | ACP 连接失败、工具调用报错 | 段落二全程依赖沙箱（Qoder CLI 在容器内跑），必须用沙箱模式重录；切勿用本地模式冒充沙箱模式 |
| Qoder CLI PAT 失效／额度耗尽 | 测试连接报 401；`_quick_verify_pat_print` 补诊断失败 | 预先在 qoder.com/account/integrations 重生 PAT，并备一个 builtin executor 的回退任务（executor 回退到 builtin 时，口播不能提 Qoder CLI，只能提「内置 ＋ 外部 CLI 双轨支持」） |
| 检查助手给出的结论与 AI助手 高度一致、无戏剧性 | 画面平淡，2D 撑不起来 | 换一个硬伤更明显的 BP 版本；2D 的台词重点放在「未验证被显式标注」（`verified=pending`）这一条上，而不是放在「抓到多少个风险」上 |
| 报告出现中英混杂或过长 | 字幕读不顺 | 录制前用同一 BP 预跑，把过长发现的展示方式在剪辑时用局部放大＋字幕改写处理；不改数据本身 |
