## 一、作品名称

**AI 技术合伙人・SecondLook**

- 中文名「AI 技术合伙人」点明产品角色：验收官 ＋ 能力教练
- 英文名 SecondLook 呼应「再看一眼」——AI 负责生成（第一眼），本产品负责把关（第二眼）

## 二、关键词（5 个）

`智能体`　`OPC 轻量化创业`　`真实问题按需补课`

## 三、作品概要

AI 能替你生成很多东西，但它们出了问题，责任仍然是你的。这是今天大学生创业者普遍面对的处境：用 AI 写出小程序、生成合作协议、做出路演材料，却看不懂、不敢改、不敢用。

AI 技术合伙人・SecondLook 是一个面向大学生个人创业（OPC）场景的双智能体智能体平台。用户把自己的项目或 AI 生成的结果（代码仓库 / 压缩包 / 合同文本）交给它，AI助手根据用户的提问和任务要求进行分析审查，按需读取代码、调用工具核验；检查助手（质检智能体）随后在后台逐条核对结论——回到真实源码取证、核查引用的外部资料是否可靠，再把无法自行确认的缺口整理成「建议深挖方向」交由用户一键触发。

在此之上，产品把审查中真实发现的问题自动改编成最小化练习，按 SM-2 遗忘曲线推送，让用户在下一次踩坑之前补上短板。练习素材 100% 来自用户自己的项目——不是题库，是你的代码。

教学产品有题库但没有你的上下文，审查工具有上下文却教不会人。AI 技术合伙人・SecondLook 两者兼得，让一个大学生的个人团队以低成本获得原本需要雇一名技术合伙人才有的判断力。

## 四、目标用户

| 层级 | 人群 | 典型处境 |
|---|---|---|
| 首要 | 大学生独立开发者 / 一人公司（OPC）创业者 | 用 AI 生成了产品，看不懂 AI 写的代码、不敢改、不敢上线，也没有技术合伙人可问 |
| 次要 | 非技术背景的学生创业者 | 要签合作协议 / 外包代开发合同、要做路演 BP，但缺乏条款与风险判断力 |
| 辐射 | 高校双创课程教师、双创基地 / 社团负责人 | 需要让学生的创业实践过程可检查、可讲评、可量化 |
| 明确排除 | 以「学会编程」为目的的通用学习者 | 存量红海，非本产品目标人群；本产品不做系统化编程教学 |

## 五、应用场景

聚焦「AI Agent 支撑个人或小团队完成从创意到落地的创业实践」，当前落地三个场景：

1. **代码交付物验收（主场景，完整可体验）**
   提交 GitHub / Gitee 仓库、ZIP 压缩包或单文件；场景模板选「代码审核」；审查维度＝安全漏洞、隐性成本（如失控的 API 调用、会烧光额度的死循环逻辑）、可维护性、能否交付上线。
2. **合同 / 协议文书审查（第二场景，轻量可用）**
   场景模板选「文书审核」，支持常见学生创业合同：合作协议、外包 / 代开发合同、兼职实习协议。审查维度＝权责对等、付款与违约、知识产权归属、常见霸王条款。出题形式为「以下条款哪一句对你不利」等判断 / 改错题。
3. **按需能力补课（贯穿两个场景）**
   审查报告中的真实问题 → 知识点看板（内置安全 / 架构 / 编程 / 合同主题，用户可自定义主题）→ 组卷练习 → 作答判分与解析 → 掌握度与「技术驾驭力」曲线。

> 场景模板架构可扩展：新增一个审查场景只需在 `backend/app/scenarios/` 注册一项，提供预设提示词与推荐技能，路由与界面自动参数化。路演材料 / BP 审查、财税报价、营销合规文案、市场调研等场景已在路线图中；本作品用「代码 ＋ 文书」两个场景证明该矩阵的可复制性，而非把它们全部铺完。

## 六、解决的教育痛点

**痛点一：双创教育里，「会用 AI 干活」被默认等于「会判断干得对不对」。**
课程鼓励学生用 AI 快速做出 MVP，但学生交上来的项目，师生其实都看不懂 AI 生成的那部分。结果是双创实践产出越来越多，验收环节却仍然靠「能跑就行」。**没有人在教学生「审」。**
→ 解法：把「审查 AI 生成物」做成产品的主功能，让每一次交付先过一道机器质检＋人话解释；再用「审查维度展示」把审查过程本身变成教学内容。

**痛点二：安全教育、合同教育、编程教育都在教，但用的都是别人的案例。**
学生做错的题、踩过的坑不在课程材料里；课程题库与学生的真实项目完全脱节，学的时候觉得懂了，下次照样踩。
→ 解法：练习题素材 100% 来自用户自己刚提交的项目，学习动机与真实风险直接挂钩；每个风险点用大白话讲清「为什么是坑、有什么后果」，支撑当下决策，而不是等学完再做决策。

**痛点三：学生创业团队请不起技术顾问，试错成本高到不敢试。**
一个学生的想法要验证，要么自己硬写、要么找人看，两种都很贵，于是多数人干脆不做。
→ 解法：把「技术合伙人」这件昂贵的事压缩成一次几分钟、零门槛的审查任务，让低成本试错真正成立。这正是 OPC 式创业的前提条件。

**痛点四：AI 生成内容进入教学与创业场景，缺少人工复核与留痕机制。**
指南「合规与安全总则」要求 AI 生成内容必须人工审核。多数 AI 工具直接把结论给用户，无法追溯结论从哪来。
→ 解法：双智能体质检本身就是内建的人工复核前置环节——检查助手不重复 AI助手的说法，而是回到真实源码逐条核对、核查引用的外部资料是否真的存在；核实不了的不硬下结论，而是在该条发现上显式标注「仅静态分析，待动态确认」。把「未取证的判断」和「已核实的事实」分开呈现，全过程流式留痕可回放。

## 七、核心功能

### 7.1 核心闭环（代码场景）

| # | 功能 | 说明 |
|---|---|---|
| 1 | 交付物提交 / 导入 | 三个来源 Tab：Git 仓库（GitHub / Gitee，支持私有仓库）／上传 ZIP／上传单文件。ZIP 做 zip-slip 穿越防护并校验单文件、总大小、文件数上限；预置典型「vibe coding 翻车」样例仓库供首次体验 |
| 2 | AI 审查（AI助手） | 按场景模板预填的维度审查：安全漏洞、隐性成本、可维护性、上线可行性；真实读取代码、执行工具，不靠猜 |
| 3 | 后台质检（检查助手） | AI助手完成后自动触发一轮完整审查：用只读工具逐条比对真实源码（或文书原文），核实声称的漏洞代码、行号与上下文是否对得上、严重度是否被夸大；抽查 AI助手 引用的 CVE／公告／官方文档是否存在且来源权威；为最值得学习的发现打 `practice_worthy` 标签；把自身无法确认的缺口整理成可一键「深挖」的建议 |
| 4 | 创业风险报告 | 结构化发现 ＋ 严重度 ＋「敢不敢上线」的明确结论 ＋ 大白话解释 ＋ 修复建议 ＋ 源码定位（同时承担「验收」与「兜底解释」两层） |
| 5 | 按需补课（自动出题） | 针对报告中的真实问题生成「看懂这段代码所需的最小知识包」；也支持直接输入主题出题（无需代码） |
| 6 | 自适应复习 | SM-2 遗忘曲线组卷：到期复习 / 薄弱点 / 难度匹配；主题级「练这个主题」与单知识点专练一键进入 |
| 7 | 成长数据 | 创始人「技术驾驭力」曲线 ＋ 项目代码健康度趋势（复查对比，体现持续迭代）；错题回顾与知识点掌握度 |

> **关于动态 PoC 验证的说明**：检查助手已具备在隔离沙箱内向测试环境发 PoC 做动态确认的工具链与安全边界（详见第十节第 5 条、第十六节），但前置条件是**被审项目有一个可访问的测试环境地址**（`test_env_url`）；未配置时系统自动降级为静态取证，并在该条结论上显式标注「仅静态分析，待动态确认」。
> **本作品的演示视频与第十二节成效数据均不包含 PoC 端到端实测结果**——该链路的实测列入第十四节后续优化方向（最优先项）；当前材料中凡涉及验证能力之处，一律指静态源码取证与外部引用核查。

### 7.2 辅助功能

- **沙箱安全执行**：基于 OpenSandbox 的容器化隔离环境，智能体的所有工具调用都在隔离容器内真实执行，不伤宿主系统；会话 TTL 自动续期，支持 CPU／内存限额
- **可插拔执行器**：内置 react_agent，或通过 ACP 协议（Agent Client Protocol）接入 Qoder CLI / DeepSeek Harness CLI / Codex CLI；沙箱内未检测到 CLI 时按官方 npm 命令自动安装
- **技能系统**：可加载专家 SKILL.md 指令（硬编码密钥检测、SQL 注入、SSRF、并发、错误处理、测试质量等），按任务勾选启用；支持用户上传自定义技能
- **智能体策略**：用户级＋任务级两层策略合并，可配置检查助手开关、动态验证权限（`per_action` 逐条人工确认 / `direct` 直连）、测试环境与凭证、AI助手确认策略；关闭检查助手即退化为单智能体模式
- **多模型配置**：用户可在设置页自行管理模型与密钥；混合思考模型可开关思考过程
- **长期记忆**：全局记忆与用户记忆分层注入，记忆生成设置可配
- **账号系统**：注册 / 登录 / 邮箱验证 / 找回密码；GitHub、Gitee OAuth 登录与私有仓库绑定
- **流式输出**：推理过程、工具调用、计划清单实时推送前端，全过程可回放

### 7.3 明确暂缓（写进后续迭代，不在本次作品中铺大）

更多审查场景（路演 BP／财税报价／营销合规／市场调研）、学习路径与能力地图、教师教练端、移动端与小程序。

## 八、AI Agent 设计思路

### 8.1 为什么是两个智能体，而不是一个更强的模型

单个 AI 审查代码的典型失效模式是**说得像真的**：报告写得漂亮，结论却没取过证，甚至引用一条不存在的 CVE。用户无法分辨，于是「审查」退化成了另一份需要被审查的 AI 生成物。

本作品的核心设计判断：**把生成与验证拆成两个职责严格分离的智能体，并让验证者优先。**

- **AI助手（执行）**：唯一被允许改动工作区的角色。按任务描述规划并完成分析，工具调用包括克隆仓库、检索代码、跑 lint、执行脚本。任务在 AI助手 完成时即标记完成，保证用户拿到结果的时间可预期。
- **检查助手（质检）**：**只读、只验、不改代码**。它自己从任务描述中定义审查维度，在后台完成一轮完整审查，输出两样东西——「关键要点／知识点」与「建议深挖方向」。它不向用户追问，而是把无法自行确认的缺口降级为建议，由用户一键触发深挖。

这个分工带来三个直接效果：结论必须回源码取证才有资格进入报告；AI助手 的过度自信会被逐条打折；「未验证」被显式标注而不是被含糊过去。

### 8.2 上下文与状态管理

- **首轮装配、后续增量**：首轮由后端组装初始上下文（仓库结构／上传文件／长期记忆），后续轮次只发送新增内容，由 CLI 侧维护会话上下文，避免每轮重复投喂整仓代码
- **会话连续性与降级**：内存中复用会话桥接；服务重启导致会话丢失时触发历史回放路径，全量重放或按段降级，保证多轮对话不断片
- **挂起保护**：无活跃工具时 300 秒空转即取消会话并以已累积内容收尾；工具运行中（如长耗时克隆／构建）保留 1800 秒兜底，防止 CLI 崩溃导致任务永久悬挂
- **跨轮记忆**：任务发现、用户偏好、项目特征沉淀为记忆，在后续任务中按需注入，使同一项目的多次复查能对比趋势

### 8.3 场景与能力扩展机制

- **场景模板**＝预设提示词 ＋ 推荐技能，把「审查该看哪些维度」从用户负担变成产品配置；场景仅作模板，不锁死流程
- **技能**＝可加载的 SKILL.md 专家指令，启动时自动扫描注册；新增一项审查能力不必改代码主干
- **执行器抽象层**＝统一 ACP 协议接口，内置智能体与外部 CLI 在同一任务模型下可切换、可对比

### 8.4 从审查到学习的数据链路

`真实发现 → 打 practice_worthy 标签 → 归入知识点看板主题 → 出题（LLM 生成，draft 预览确认后才入库）→ SM-2 排期 → 作答判分与解析 → 掌握度回流成长数据`

出题不是独立功能，而是审查结果的下游投影。因此题库不可能与学生项目无关——这是本产品与一切通用刷题工具最根本的结构差异。

## 九、OPC 式实践体现

指南要求作品体现「低成本启动、小团队协作、AI 辅助执行、快速验证、持续迭代」，且不能只是普通 AI 问答工具或单一功能页面。逐条对应：

| OPC 特征 | 本作品如何支撑 | 可演示证据 |
|---|---|---|
| **低成本启动** | 一个人不需要雇技术合伙人、不需要读懂全部生成代码，就能对交付物做出可担责的判断；网页端直接使用，零部署门槛 | 演示段落 2：从登录到拿到风险结论的完整一次任务 |
| **小团队协作** | 同一份风险报告即团队共识基线：严重度排序直接给出「谁先改哪个」；审查维度、启用技能、验证权限可按任务覆盖，适配不同分工成员；发现与源码定位可截图进周会 | 报告中多条发现＋严重度＋源码定位；任务级「高级设置」抽屉 |
| **AI 辅助执行（不是 AI 代劳）** | 关键差异：两个智能体的分工是**执行 ＋ 验证**，而非生成更多。AI 负责读代码、回源码核实、核对引用；决策权留给用户；未取证的判断被显式降级为「建议深挖方向」或标注「待动态确认」 | 检查助手「检查完成」标记、逐条核实结果、一键「深挖」 |
| **快速验证** | 想法落地后先过机器质检而不是先找人看：分钟级拿到「敢不敢上线」的结论，试错成本从「几天找人看」压到「一次任务」 | 演示中单次任务的真实耗时 |
| **持续迭代** | 修复后复查同一仓库，健康度趋势可见；练习按遗忘曲线到期推送；记忆沉淀让后续任务更贴合该项目 | 成长数据曲线、SM-2 到期复习、复查对比 |

**产品自我检验标准**（防止滑回学习工具）：每个功能都要自问「如果用户永远不做练习，这个产品对他还有用吗？」答案必须是「有用」——风险报告本身值回使用它的时间。三层定位顺序不可颠倒：验收（进来的理由）→ 兜底解释（能拍板，而非成专家）→ 按需补课（差异化与留存）。

## 十、技术创新点

1. **验证者优先的双智能体质检机制**（不是两个 AI 闲聊）
   检查助手被剥夺改代码的权限，只有取证职责：回源码（或文书原文）逐条比对、抽查外部引用的真实性与权威性、核实不了时不硬判。「AI 说的」和「验过的」在报告里是两类东西。
2. **审查结论直接生成教学内容——素材同源，不需要题库**
   练习题由用户自己项目里的真实发现改编而来，`practice_worthy` 标签决定出题优先级。同一份审查上下文既产出风险报告又产出练习，这是「审查 ＋ 出题」共用一套上下文的架构结果，而非在审查工具上加了个刷题页。
3. **「敢不敢上线」的决策式输出，而非技术分数**
   报告终点是一个非技术创始人能做决定的结论＋大白话后果解释，把结构化风险翻译成创业决策。
4. **可插拔执行器抽象层（ACP 协议）**
   内置 ReAct 智能体与外部 CLI（Qoder / DeepSeek Harness / Codex）在同一任务模型下可切换；更换执行层不改业务主干，使产品能持续吃到最新智能体能力红利。
5. **结论自带「取证状态」，把不确定性显式交给用户**
   每条发现的元数据带 `verified` / `verify_method` / `ref_status` 等状态位：是经源码核实、经引用核查，还是「仅静态分析，待动态确认」。用户一眼能分清哪些结论可以直接拿去拍板、哪些还需要自己再看一眼。多数审查工具把所有结论以同等确定性呈现给用户，而这恰恰是 AI 生成物最危险的地方。
   支撑这一点的验证工具链已实现并带安全边界：PoC 请求的 base 地址锁定为任务配置的测试环境、不可由模型篡改（防 SSRF），逐条人工授权可选，执行落在隔离容器内。因需要被测项目提供可访问的测试地址，本作品**尚未完成该链路的端到端实测**，故不纳入演示与成效数据。
6. **场景矩阵的可复制架构**
   审查＋出题的组合不绑定代码：文书审核场景以极小成本接入，证明同一架构可迁移到合同、路演、财税等创业任务，支撑「AI Agent 支撑个人或小团队完成创业任务」这一赛道主线，而不是做一个单点功能页面。

## 十六、安全与合规机制

对应指南「十一、合规与安全总则」及评分项「技术规范性（25 分）」：

- **AI 内容人工复核**：检查助手作为强制的第二道验证，把未取证判断降级为需用户主动触发的建议；报告支持用户反馈修正，题库条目须经 draft 预览确认才入库
- **凭证与隐私保护**：Git 访问令牌以 Fernet 对称加密存储；日志在处理器层统一脱敏（令牌值过滤为 `***`），Gitee 将 access_token 置于 URL 查询串并被 httpx 以 INFO 记录的情况已专门覆盖；克隆完成后从工作区抹除带令牌的 URL，防止泄露随下载扩散
- **数据最小化与授权范围**：Gitee 仅申请 `user_info`（登录）与 `projects`（仓库绑定）两项必要 scope，不过度索取权限
- **执行环境隔离**：智能体的所有工具调用运行在容器化沙箱内，受 CPU／内存限额与会话超时回收约束；动态验证权限支持逐条人工确认（`per_action`）与直连（`direct`）两种模式，由用户选择；PoC 请求的 base 地址锁定为任务配置的测试环境、不可由模型篡改，后端服务器地址不暴露给测试环境（防反向探测与 SSRF）
- **危险操作确认**：「AI助手确认策略」可要求命令级人工确认
- **上传安全**：ZIP 做 zip-slip 路径穿越防护及大小／数量上限校验；二进制文件不做在线预览，仅提供下载
- **接口与故障安全**：对外部平台调用按错误语义分类（平台明确拒绝 / 令牌失效 / 幂等可重试的网络与 5xx），单一用途的授权码绝不重放
- **SSRF 加固**：智能体核查外部引用（CVE / 公告 / 官方文档）时对内网地址与内网解析做防护
- **合规取向**：优先选用符合国内数据安全与网络监管要求的模型与平台；作品面向高等教育与创业实践场景，不涉及未成年人数据采集
- **竞赛纪律**：全程本人 / 本团队独立完成，无代赛、无场外协助、无材料造假
