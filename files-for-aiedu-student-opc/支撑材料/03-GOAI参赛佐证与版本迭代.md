## 二、本版相对上一版（agentpair → SecondLook）的具体改进

核心增量：

| 方向 | 上一版 `agentpair` | 本版 `SecondLook` | 价值 |
|---|---|---|---|
| **智能体架构** | 单一 `user_agent` 做“覆盖度评估” | 拆为 **agent1（执行／“AI助手”）+ agent2（验证优先质检／“检查助手”）** 职责分离：agent2 被剥夺改码权限，只**回源码取证**、**复核外部引用**、**必要时生成 PoC** | 直击“报告写得像真的却没取证”的失效模式 |
| **交付物来源** | 以 Git 仓库为主 | 新增 **ZIP 压缩包 + 单文件上传**，含 **zip-slip 路径穿越防护**与大小/数量上限 | 为**合同/文书审查**场景打通输入，验证“审查+出题”架构可跨场景迁移 |
| **执行器抽象** | 多而散（含 kimi / qoder_cn / hermes 等） | **收敛为 3 种并统一到 ACP 协议**：Qoder CLI / DeepSeek Harness(dsh) / Codex；内置 `react_agent` 与外部 CLI 可插拔切换 | 更换执行层不改业务主干，可持续吸收最新智能体能力 |
| **出题链路** | 出题能力零散 | 出题明确归为 **agent2 下游职责**：真实发现打 `practice_worthy` → 知识点看板 → LLM 出题（**draft 预览确认后才入库**）→ **SM-2 排期** → 判分解析 | 素材 100% 来自用户自己项目，构成“审查→学习”闭环 |
| **场景矩阵** | 偏代码单点 | 代码审查 + **文书/合同审查**双场景落地，其余场景进 Roadmap | 支撑“AI Agent 帮个人/小团队完成创业任务”主线，而非单功能页 |
