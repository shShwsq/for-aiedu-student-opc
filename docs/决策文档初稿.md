# AI 技术合伙人・SecondLook · 产品决策文档

> 参赛方向：大学生 OPC 创新创业 AI Agent 赛道

## 产品定位与背景

### 定位

**产品一句话：OPC 创业者的 AI 技术合伙人・SecondLook——AI 能替你生成一切，但生成物出了问题，责任是你的。**

**命名说明**：中文主名「AI 技术合伙人」点明产品角色（验收官 + 能力教练）；英文品牌名 SecondLook 呼应「再看一眼」——AI 负责生成（第一眼），本产品负责把关（第二眼）。

产品面向用 AI 干活、但对 AI 产出"心里没底"的大学生创业者：先审查 AI 生成的交付物（代码、合同、路演材料），告诉用户敢不敢用、敢不敢签、敢不敢上线；再针对真实发现的问题，按需生成最小化的能力练习，让用户在下一次踩坑前补上短板。

核心观点：AI 时代创业的门槛不是"会不会写"，而是"敢不敢收"。每个 OPC 创业者都需要一个 AI 技术合伙人——不是替他干活，而是帮他验收、帮他变强。

### 定位三层（顺序不可颠倒）

1. **验收（用户进来的理由）**：审查 AI 生成物，输出风险报告，解决当下的真实风险。
2. **兜底解释（能拍板，而非成专家）**：每个风险点用大白话讲清"为什么是坑、有什么后果"，支撑用户做决策。
3. **按需补课（差异化与留存）**：把真实问题改编成最小化练习，按遗忘曲线推送。不强迫、不系统化教学。

**设计检验标准**：每个功能自问——"如果用户永远不做练习，产品对他还有用吗？"答案必须是"有用"（审查报告本身值回票价）。否则说明又滑回了学习产品。

### 目标用户

- **首要**：大学生独立开发者 / 一人公司（OPC）创业者——正在用 AI 生成代码做产品，但看不懂、不敢改、不敢上线
- **次要**：非技术背景的学生创业者——需要签合作协议、外包合同、做路演 BP，但缺乏判断力
- **排除**：以"学会编程"为目的的学习者（存量红海，非目标人群）

### 主要价值

- **对创业者**：AI 产出物的"验收官 + 能力教练"，低成本获得技术/法务判断力
- **对大赛**：精准命中"AI Agent 支撑个人或小团队从创意到落地"的赛道主题，体现 OPC 特征（低成本启动、快速验证、轻量运营、持续迭代）
- **差异化**：教学产品有题库但没上下文，审查工具有上下文但教不会人——本产品两者兼得，且练习素材 100% 来自用户自己的真实项目

## 产品功能清单

### 核心闭环（MVP，代码场景）

1. **交付物提交/导入**：创业者提交 AI 生成的代码仓库（GitHub/Gitee 链接或 .zip 上传；预置若干典型"vibe coding 翻车"样例仓库供体验）
2. **AI 审查（agent1，"AI CTO"视角）**：按维度审查——安全漏洞、隐性成本（如失控 API 调用、死循环烧钱逻辑）、可维护性、能否交付上线；agent2 质检审查结果，必要时追问补全
3. **创业风险报告**：结构化发现 + 严重度 + "敢不敢上线"的明确结论 + 大白话解释 + 修复建议 + 源码定位（承担"验收"与"兜底解释"两层）
4. **按需补课（agent2 出题）**：针对报告中的真实问题，生成"看懂这段代码所需的最小知识包"；练习素材全部来自用户自己的代码
5. **自适应复习**：SM-2 遗忘曲线组卷（到期复习 / 薄弱点 / 难度匹配）
6. **即时反馈**：作答判分 + 解析 + 知识点掌握度
7. **成长数据**：创始人"技术驾驭力"曲线 + 项目代码健康度趋势（复查对比，体现持续迭代）

### 第二场景（轻量验证版，文书审核）

- 支持上传常见学生创业合同类型（合作协议、外包/代开发合同、兼职实习协议 2–3 类即可）
- 审查维度：权责对等、付款与违约、知识产权归属、常见霸王条款
- 出题形式："以下条款哪一句对你不利"等判断/改错题
- 目标不是做全，而是证明"审查 + 出题"架构的通用性，支撑平台叙事

### 辅助功能

- 沙箱安全执行（分析过程真实运行、不伤系统；安全维度 PoC 演示在此进行）
- 多 LLM 模型配置（用户可选模型）
- 题库管理（draft 预览确认、归档）
- 账号系统（注册 / 登录 / 邮箱验证 / 找回密码）

### 暂缓功能（后续迭代）

- 更多审查场景：路演材料/BP（agent2 化身评委追问，演示效果最佳，决赛后优先）、财税报价、营销合规文案、市场调研
- 学习路径 / 能力地图
- 移动端 / 小程序

## 大赛参赛适配

### 叙事主线（对应评审关注重点）

演示视频脚本：大学生用 AI 生成小程序 MVP → 提交给 AI 技术合伙人・SecondLook → 拿到风险报告，发现会刷爆 API 额度的死循环/真实漏洞 → 通过定制练习看懂问题 → 自行修复并上线。一条链路同时讲清：用户提出任务 → Agent 执行 → 生成结果 → 用户应用结果 → 支撑低成本启动、快速验证、持续迭代。

### 对应评分框架

| 评分项 | 应对策略 |
|---|---|
| 场景适配性（20 分） | 真实痛点：vibe coding 创业者"不敢上线"；文书审核场景覆盖非技术创始人 |
| 技术规范性（25 分） | 「执行 + 后台质检」机制；沙箱隔离；说明模型与工具来源合规 |
| 创新优化性（20 分） | "审查 + 按需补课"组合区别于一切代劳型创业助手和通用审查工具 |
| 实施显著性（25 分） | ~~报名截止前收集真实试用数据：发现高危问题数、修复前后对比、用户反馈~~（做不到） |
| 推广适配性（10 分） | "审查场景矩阵" roadmap 图，证明架构可复制到文书、路演、财税等场景 |

### 参赛策略要点

- **做透一个 + 彩蛋一个**：代码审核场景完整可体验；文书审核场景轻量可用；其余只进 roadmap，不铺大
- **材料清单**：按官网要求准备申报书、作品介绍文档（含 3–5 关键词、OPC 式实践体现）、≤10 分钟演示视频（概述 ≤2min / 核心演示 ≤6min / 总结 ≤2min）、试用数据支撑材料
- **作品名称**：AI 技术合伙人・SecondLook（申报书、作品介绍文档、演示视频开场统一使用；英文名 SecondLook 可作视觉品牌副标）
- **时间节点**：报名 2026-06-29 至 10-15；预赛 10-16 至 10-31；决赛 11 月初
